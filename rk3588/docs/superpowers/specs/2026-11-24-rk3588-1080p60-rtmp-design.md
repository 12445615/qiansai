# RK3588 1080p60 RTMP 全量变更整合设计

## 目标

将 `/home/chx/Linux/qiansai/rk3588` 当前工作区中的全部有效工程变更整合到独立分支 `rk3588-1080p60-rtmp`，使用 ELF2 Jammy 部署配置、FFmpeg ABI 60 和 `h264_rkmpp` 完成可复现构建，并在 RK3588 真机上验证 1920×1080、约 60fps 的采集、编码和 RTMP 推流，同时回归 AI、Recovery、存储、MQTT、Modbus、安全联锁和服务生命周期。

## 基线与隔离

- Git 基线：`codex/elf2-build-env`，提交 `d607021`。
- 隔离 worktree：`/home/chx/.config/superpowers/worktrees/qiansai/rk3588-1080p60-rtmp`。
- 写入远端：`fork = https://github.com/chhhx943/qiansai.git`。
- 原工作区只作为候选变更来源，不在其中执行清理、暂存、提交或回退。
- 所有导入操作必须按明确文件清单执行，不能复制整个目录覆盖隔离 worktree。

## 纳入范围

纳入当前 `rk3588/` 工作区内全部有工程意义的变更：

1. 1080p60 视频链：相机格式、stride/padding、RGA、MPP 编码、RTMP、帧率协商和重连。
2. AI/NPU：1080p 输入下的缩放、dma-buf、多核推理、队列和区域检测适配。
3. Recovery：类型、编译器、运行时、proof barrier、冻结语义、compile-fail 与生命周期测试。
4. 本地存储与上传：SQLite、视频分片、离线上传、存储根目录和水位控制。
5. MQTT、Modbus、安全联锁和音频告警的现有有效修改。
6. Jammy 构建配置、依赖检查、SDK 安装脚本、测试脚本和正式技术文档。

## 排除范围

以下内容不进入 Git：

- `*.bak*`、旧版本快照和重复备份源码；
- `main`、`*.o`、`*.d`、测试二进制及其他构建产物；
- 临时日志、抓帧、视频、数据库、缓存和实验输出；
- 能从源码重新生成的迁移目录或 sysroot 内容；
- 与当前工程无关的个人环境文件。

排除只针对无复用价值的副本和产物，不排除对应的正式源码改动。

## 变更筛选方法

1. 记录原工作区 tracked/untracked 清单和每个文件的差异摘要。
2. 对 tracked 文件逐个把工作区版本与基线版本比较；仅在确认属于有效工程状态后导入。
3. 对 untracked 文件按类型分类：正式源码、测试、脚本、文档纳入；备份和构建产物排除。
4. 导入后执行 `git diff --check`、路径清单复核和敏感信息扫描。
5. 不使用 `git add -A`；每个提交按显式文件列表暂存。

## 构建环境

- Profile：`jammy-deploy`。
- 工具链：`~/.local/opt/elf2-sdk/toolchains/gcc-arm-10.3-aarch64/bin/aarch64-none-linux-gnu-*`。
- Sysroot：`~/.local/opt/elf2-sdk/profiles/jammy-deploy/sysroot`。
- FFmpeg：ABI 60，要求 `libavcodec.so.60`。
- 编码器证据：manifest 必须包含固定 FFmpeg Rockchip commit、`CONFIG_H264_RKMPP_ENCODER=1` 和 `CONFIG_AAC_ENCODER=1`。
- 严格依赖：Paho MQTT C、libmodbus、Rockchip MPP、RGA、RKNN 必须全部存在；缺任一项则禁止生成部署候选物。

## 验证分层

### 1. 静态与配置验证

- profile、SDK、Jammy 依赖、FFmpeg 6 RKMPP、strict env、ELF dependency tests；
- `git diff --check`、备份文件/构建产物扫描；
- 编码器名、RTMP URL、分辨率、帧率和 stride 常量检查。

### 2. 主机侧测试

- 全部 `make test` 测试；
- Recovery build、runner、compile-fail、digest、boundary、proof、freeze 和 lifecycle 测试；
- 本地存储、视频分片、可选依赖和构建配置测试；
- `PROFILE=jammy-deploy` 的 clean full build；
- 对生成 ELF 执行 `readelf`、`file`、依赖闭包和架构检查。

### 3. 板端部署前检查

- 保存当前 `/root/main` 的 MD5、版本与可执行备份；
- 记录服务状态、内核版本、相机 media graph、现有 capture/stream fps、IOMMU fault 计数；
- 先上传到临时路径并执行依赖/编码器初始化探针，禁止直接覆盖生产文件。

### 4. 板端功能回归

- 输入与输出严格为 1920×1080，采集和推流稳定在至少 59fps；
- H.264 RTMP 可由 WSL `ffprobe` 和 Qt 客户端订阅；
- 完整彩色画面，无全黑、死行、错误色度、拉伸和周期错位；
- `stream_failures=0`，无 CSI/IOMMU fault；
- AI 三核任务持续运行，无队列失控；
- MQTT、Modbus、STM32、安全联锁、音频告警、SQLite、视频分片和上传路径完成冒烟回归；
- `rk3588-main.service` 重启后仍恢复正常。

### 5. 稳定性验收

- 板端与 Qt 进行至少 600 秒端到端运行；
- 记录 capture/stream/decode/render fps、失败计数、RSS、温度和磁盘变化；
- 关键判据为 1920×1080、解码/显示至少 59fps、0 推流失败和无资源持续增长。

## 失败处理与回退

- 任一 strict 构建条件或关键测试失败，停止进入下一层，按首个失败点做根因定位。
- 临时板端候选物初始化失败时不替换生产程序。
- 已替换后出现功能回归，立即恢复备份 `/root/main`、重启服务并执行生产自检。
- 不用跳过测试、放宽 linker 检查或二进制字符串补丁掩盖源码/工具链问题。
