# Qt 1080p60 RTMP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the WSL Qt client render the RK3588 H.264 RTMP stream at 1920×1080 and a measured presentation rate of at least 59fps without unbounded GUI event-queue growth.

**Architecture:** Keep FFmpeg decoding in `XVideoThread`, replace live-view per-frame queued signals with a capacity-one thread-safe latest-frame mailbox, and let `PageCamera` consume that mailbox from a precise 16ms GUI timer. Convert directly to the current aspect-fitted display size, expose measured decode/render/overwrite statistics, and reconnect live inputs after recoverable read failures.

**Tech Stack:** Qt 6.5.3 Widgets/QtTest, FFmpeg libavformat/libavcodec/libswscale, qmake, nginx-rtmp on WSL.

- [ ] **Step 3: Implement the minimal runtime core**

Define this stable interface:

```cpp
struct VideoFrameSnapshot {
    QImage image;
    quint64 sequence = 0;
    qint64 ptsMs = 0;
    qint64 producedAtMs = 0;
};

class VideoFrameMailbox {
public:
    quint64 publish(const QImage &image, qint64 ptsMs, qint64 producedAtMs);
    bool takeLatest(quint64 lastSequence, VideoFrameSnapshot *frame);
    void clear();
    quint64 overwrittenFrames() const;
private:
    mutable QMutex m_mutex;
    VideoFrameSnapshot m_latest;
    quint64 m_lastTakenSequence = 0;
    quint64 m_overwrittenFrames = 0;
};

class VideoRateSampler {
public:
    double sample(qint64 nowMs, quint64 total);
    void reset();
private:
    qint64 m_lastMs = -1;
    quint64 m_lastTotal = 0;
};

QSize fitVideoInside(const QSize &source, const QSize &bounds);
```

`publish()` increments overwrite count only when an unread frame is replaced. `takeLatest()` returns false for null output, empty mailbox, or an already seen sequence. `fitVideoInside()` returns an empty size for invalid inputs and uses integer-safe aspect fitting.

The status text format must be:

```text
输入 1920x1080  码流 59.9fps  解码 59.9fps  显示 59.8fps  覆盖 N
```

- [ ] **Step 2: Replace live per-frame queued delivery**

For `logPrefix == "RTMP"`, do not connect `sig_SendOneFrame`. Start a precise timer at 16ms and on each timeout:

1. send the current aspect-fitted label size to `setOutputSize()`;
2. call `takeLatestFrame(lastSequence, &frame)`;
3. update `QLabel` with `QPixmap::fromImage(frame.image)` only for a new sequence;
4. increment rendered total;
5. once per second sample decoder/render totals and update the status label.

Keep the existing queued-signal playback path for local recordings so seeking and variable playback rate retain their current behavior.

- [ ] **Step 3: Make lifecycle cleanup explicit**

Stop the live render timer before stopping/deleting `liveVideoThread`. Reset sequence/rate counters on every new live connection. Clear the displayed pixmap on reconnect failure so an old frame is never presented as current.
